# ข้อความ

[สารบัญ](README.md) · ก่อนหน้า: [Sync](sync.md) · ถัดไป: [Letter Sealing](letter-sealing.md)

หน้านี้ครอบคลุมรายการแชต การอ่านประวัติ struct Message การส่งข้อความ และทุกอย่างที่ทำกับข้อความได้ ส่วนการเข้ารหัสอยู่ในหน้า [Letter Sealing](letter-sealing.md) และไฟล์แนบอยู่ในหน้า [มีเดีย](media.md) เกือบทั้งหมดอยู่ใน [`messaging.c`](../../src/messaging.c) ส่วนการจัดการคำขอฝั่ง worker อยู่ใน [`main.c`](../../src/main.c)

## รหัสแชต

แชตระบุด้วย MID (ดู [ภาพรวม](overview.md))

- **แชตตัวต่อตัว** ใช้ MID `u…` ของ *อีกฝ่าย*
- **กลุ่ม** ใช้ MID `c…` ของกลุ่ม
- **ห้อง** (แชตหลายคนแบบเก่า) ใช้ MID `r…`
- MID `u…` ของตัวคุณเองคือแชต **Keep Memo**

`talk_id()` ใน `messaging.c` ตรวจรูปแบบ 33 ตัวอักษร worker เก็บรหัสแชตทุกตัวที่เคยเห็นไว้ใน `w->chats` และปฏิเสธคำขอสำหรับรหัสอื่น UI จึงถูกหลอกให้ทำอะไรกับ MID สุ่ม ๆ ไม่ได้

## รายการแชต

ลากขอบแบ่งระหว่างรายการแชตกับบทสนทนาเพื่อปรับความกว้างของแถบด้านข้าง แอปจะจำความกว้างไว้เมื่อเปิดครั้งถัดไป ลากแถบเลื่อนเพื่อเลื่อนดูรายการแชตหรือข้อความที่โหลดแล้ว หากต้องการโหลดข้อความเก่ากว่านั้น ให้กด **ข้อความก่อนหน้า**

`line_chats()` สร้างรายการจาก **message box** ซึ่งเป็นสถานะการส่งของแต่ละแชตใน LINE ไม่ได้สร้างจากอ็อบเจกต์แชตเต็มรูป

**คำขอ** `getMessageBoxes` บน `/S4` ด้วย `{2: {1: cursor, 3: true (activeOnly), 4: 100 (จำนวน), 5: true (withUnreadCount), 6: 0, 7: false}, 3: 7}` หน้าแรกไม่ใส่ cursor หน้าถัดไปใช้รหัสแชตของ box ตัวสุดท้าย ถ้าฟิลด์ 2 ของคำตอบ ("ยังมีอีก") เป็นจริง จะดึงหน้าถัดไป ถ้า cursor ซ้ำเดิมถือเป็นข้อผิดพลาด ("LINE did not advance the chat list")

**แต่ละ box** (ฟิลด์ 1 ของคำตอบคือรายการ) อ่านดังนี้

| ฟิลด์ | ความหมาย |
| ----- | -------- |
| 1 | รหัสแชต |
| 4 | ข้อความล่าสุดที่ส่งถึง: ฟิลด์ 1 คือเวลา ฟิลด์ 2 คือรหัส |
| 5 | รหัสข้อความล่าสุดที่คุณเห็นแล้ว (อ่านถึงตรงนี้) |
| 6 | จำนวนที่ยังไม่อ่าน |
| 8, 10 | รหัสข้อความที่ "ลบ" และ "ซ่อน" ถ้าข้อความล่าสุดของแชตอยู่ที่หรือต่ำกว่าค่าที่มากกว่าในสองตัวนี้ แปลว่าแชตถูกล้างหรือซ่อน จึงข้ามไป |

**ชื่อ** box ไม่มีชื่อมาด้วย `line_resolve_names()` เติมให้

- ผู้ใช้ด้วย `getContactsV3` บน `/RE4` (หรือ `getContactsV2` บน `/S4` สำหรับเซิร์ฟเวอร์รุ่นเก่า) แคชไว้ใน `s->profiles` ตลอดเซสชัน
- กลุ่มและห้องด้วย `getChats` บน `/S4` ด้วย `{1: {1: [ids], 2: false, 3: false}}` อ่านชื่อจากฟิลด์ 6 ของแชต
- แชตของตัวคุณเองชื่อ "Keep Memo"

**แถวที่ส่งให้ UI** เรียงจากใหม่สุด

```json
{"id": "c…", "name": "Family", "time": 1764000000000, "unread": 3,
 "lastId": "5125…", "lastSeenId": "5120…", "avatarKey": "/0h…", "clearThrough": 0}
```

`chat_directory()` ของ worker ใน `main.c` จำแถวเหล่านี้ไว้ด้วย เพื่อใช้ตรวจรหัสแชต ข้อความล่าสุดที่ยังไม่อ่าน และประกาศ

## struct Message

ข้อความจากประวัติและจาก sync ใช้ struct ของ Thrift ตัวเดียวกัน ฟิลด์ที่ไคลเอนต์อ่านและเขียน

| ฟิลด์ | ชื่อ | หมายเหตุ |
| ----- | ---- | -------- |
| 1 | from | MID ผู้ส่ง |
| 2 | to | MID ผู้รับ: ผู้ใช้ กลุ่ม หรือห้อง |
| 3 | toType | 0 ผู้ใช้, 1 ห้อง, 2 กลุ่ม |
| 4 | id | รหัสข้อความ เป็นสตริงตัวเลขฐานสิบ เพิ่มขึ้นตามเวลา |
| 5 | createdTime | มิลลิวินาทีแบบ Unix |
| 6 | deliveredTime | มิลลิวินาทีแบบ Unix ใช้แบ่งหน้าประวัติ |
| 10 | text | ข้อความธรรมดา สำหรับข้อความที่ไม่เข้ารหัส |
| 11 | location | สำหรับข้อความตำแหน่ง ฟิลด์ 2 คือที่อยู่ |
| 14 | hasContent | |
| 15 | contentType | ดูตารางถัดไป |
| 18 | contentMetadata | `map<string,string>`: metadata ที่เดินทาง **นอก** การเข้ารหัส |
| 19 | sessionId | ส่งเป็น 0 |
| 20 | chunks | `list<binary>`: ซองจดหมายของ Letter Sealing |
| 21 | relatedMessageId | ข้อความที่ข้อความนี้ตอบกลับ |
| 22 | messageRelationType | 3 หมายถึงการตอบกลับ |
| 24 | relatedMessageServiceCode | 1 สำหรับการตอบกลับในบริการ Talk เดียวกัน |
| 27 | reactions | รายการรีแอ็กชัน แต่ละตัวมีฟิลด์ 3 ซึ่งฟิลด์ 1 ข้างในคือชนิดรีแอ็กชัน |

### ชนิดเนื้อหา

ค่าของ `contentType` (ฟิลด์ 15) และชื่อที่ worker ใช้ในแถว (`kinds[]` ใน `history_rows()`)

| ค่า | ชื่อ | ค่า | ชื่อ |
| --- | ---- | --- | ---- |
| 0 | text | 12 | link |
| 1 | photo | 13 | contact |
| 2 | video | 14 | file |
| 3 | audio | 15 | location |
| 4 | html | 16 | post |
| 5 | pdf | 17 | rich (imagemap) |
| 6 | การโทรหรือเหตุการณ์ในแชต | 18 | เหตุการณ์ในแชต |
| 7 | sticker | 19 | music |
| 8 | presence | 20 | payment |
| 9 | gift | 21 | externalImage |
| 10 | board | 22 | flex |
| 11 | app | | |

ค่าอื่นแสดงเป็น "other"

ประวัติการโทรจะแสดงประเภท ผลลัพธ์ และระยะเวลาที่ LINE ส่งมา `DURATION` มีหน่วยเป็นมิลลิวินาที การเริ่ม สิ้นสุด และคำเชิญเข้าร่วมการโทรกลุ่มจะแสดงเป็นข้อความตรงกลาง ส่วนเหตุการณ์อื่นใช้ `LOC_KEY` ระบุการกระทำ และใช้ `LOC_ARGS` สำหรับชื่อ หากไม่รู้จักเหตุการณ์จะแสดงข้อความจาก LINE เมื่อมี

### คีย์ metadata ที่จะเจอ

| `contentType` | ชนิดเนื้อหาซ้ำอีกครั้งในรูปสตริง (`"0"` สำหรับข้อความ) |

| `STICON_OWNERSHIP` | ชุดอีโมจิ LINE ที่ใช้ ดูด้านล่าง |
| `REPLACE` | อีโมจิ LINE ในข้อความที่ *ไม่เข้ารหัส* |
| `SID`, `OID`, `FILE_SIZE`, `FILE_NAME`, `DURATION`, `MEDIA_CONTENT_INFO` | ไฟล์แนบ ดู [มีเดีย](media.md) |

| `DOWNLOAD_URL`, `PREVIEW_URL` ในข้อความรูปภาพ | รูปของบัญชีทางการและรูปขนาดเล็ก ดู [มีเดีย](media.md#การดาวน์โหลด) |
| `displayName` | การ์ดผู้ติดต่อ |

## การอ่านประวัติ

### หน้าล่าสุด

`line_history_with_summary()` เรียก `getRecentMessagesV2` บน `/S4` ด้วย `{2: chat, 3: 50}` ถ้า LINE ตอบเป็นหน้าว่าง ขณะที่รายการแชตบอกว่าแชตนี้มีข้อความล่าสุด จะลองใหม่จากตำแหน่งของข้อความนั้นด้วยการเรียกหน้าเก่า เพราะบางเซิร์ฟเวอร์ตอบการเรียกหน้าล่าสุดว่างเปล่าหลังมีช่องว่างของข้อมูล

### หน้าเก่ากว่า

`line_history_older_since()` เรียก `getPreviousMessagesV2WithRequest` ด้วย `{2: {1: chat, 2: {1: deliveredTime, 2: รหัสข้อความ}, 3: 50}, 3: 7}` ขอบเขตคือข้อความเก่าสุดในหน้าปัจจุบัน (`line_history_cursor()` เลือก `deliveredTime` ที่น้อยที่สุด แล้วรหัสที่น้อยที่สุด) การแบ่งหน้าหยุดที่รหัส "ล้างถึง" ของแชต ประวัติที่คุณล้างบนโทรศัพท์จึงยังถูกล้างอยู่

### จาก Message เป็นแถว

`history_rows()` แปลง Message ดิบเป็นแถวที่ UI วาดได้

```json
{"id": "5125…", "from": "Alice", "senderId": "u…", "own": false, "time": 1764000000000,
 "type": "text", "text": "hello", "emojis": [...], "replyTo": "5120…",
 "reactions": {"love": 2}, "avatarKey": "/0h…"}
```

ระหว่างทาง

- **ข้อความ** (ชนิด 0): ข้อความที่ปิดผนึกถูกเปิดด้วย `line_open_payload()` ถ้าอุปกรณ์นี้ไม่มีกุญแจรุ่นนั้น ข้อความจะกลายเป็น "[Letter Sealing key missing on this device]" ความล้มเหลวอื่นกลายเป็น "[Unable to decrypt this message]" ทั้งสองแบบแถวจะมี `"unreadable": true` ช่วงอีโมจิ LINE มาจาก `REPLACE.sticon.resources` ของ payload (หรือจาก metadata สำหรับข้อความที่ไม่เข้ารหัส)
- **Flex** (22): `add_flex()` ตรวจ `FLEX_JSON` (ไม่เกิน 64 KiB) แล้วใส่ในแถว ข้อความกลายเป็นข้อความแทน (alt text)
- **Rich** (17): `line_rich_parse()` ([`rich_message.c`](../../src/rich_message.c)) สร้างโครงการจัดวางแบบกะทัดรัด ดู [มีเดีย](media.md)
- **วิดีโอ** (2): `DURATION` กลายเป็น `durationMs`
- **ไฟล์และวิดีโอ**: `FILE_NAME` กลายเป็น `filename` เมื่อ `line_received_filename()` ยอมรับ คือเป็น UTF-8 ที่ถูกต้องยาวไม่เกิน 255 ไบต์ ไม่มีเครื่องหมายทับ เครื่องหมายทับกลับ อักขระควบคุม หรืออักขระสลับทิศทางข้อความ และไม่ขึ้นต้นด้วยจุด ผู้ส่งจึงอำพรางนามสกุลไฟล์หรือเสนอไฟล์ซ่อนอย่าง `.bash_profile` ไม่ได้ ชื่ออื่นจะแสดงและบันทึกเป็น `attachment`
- **ตำแหน่ง** (15), **ผู้ติดต่อ** (13): ที่อยู่หรือชื่อที่แสดงกลายเป็นข้อความ
- **รีแอ็กชัน**: นับตามชนิด
- **ชื่อ**: ผู้ส่งถูกค้นชื่อผ่านแคชโปรไฟล์ ข้อความของคุณเองแสดงว่า "You"

แถวเรียงตามเวลา แล้วตามรหัส Message ดิบก็ถูกเก็บไว้ด้วย โดยใช้รหัสเป็นคีย์ใน `w->messages` worker ต้องใช้มันภายหลังเพื่อตอบกลับ รีแอ็กชัน ส่งต่อ ดาวน์โหลดไฟล์แนบ หรือสร้าง URL ของสติกเกอร์ และไม่เคยเชื่อข้อความที่ UI ส่งกลับมา

### แคชประวัติ

worker เก็บหน้าของแชตที่เพิ่งเปิดไว้ในแคชแบบ LRU (`history_cache` ใน `struct line_worker`) การเปิดแชตอีกครั้งจะตอบจากหน่วยความจำทันที แล้ว **ตรวจซ้ำ** กับ LINE ตามหลัง (`revalidate_history()`) และส่งอีเวนต์ `history` ถ้ามีอะไรเปลี่ยน ข้อความใหม่ในแชตจะทำเครื่องหมายว่าแคชของแชตนั้นล้าสมัย หรือทิ้งไปถ้าแชตไม่ได้เปิดอยู่

## การส่งข้อความ

`send` ด้วย `{chat, text, replyTo?, emojis?, mentions?}` ไปถึง `line_send_decorated()`

1. **ตรวจสอบ** ข้อความต้องเป็น UTF-8 ที่ไม่ว่างและยาวไม่เกิน 20,000 ไบต์ `replyTo` ต้องเป็นข้อความในแชตที่เปิดอยู่
2. **สร้าง payload** `{"text": "…"}` และถ้ามีอีโมจิ LINE ก็เพิ่ม `{"REPLACE": {"sticon": {"resources": [...]}}}`
3. **ปิดผนึก** ด้วย `line_seal_payload()` (ชนิดเนื้อหา 0) ดู [Letter Sealing](letter-sealing.md)
4. **สร้าง metadata**: `e2eeVersion: "2"`, `contentType: "0"`, `e2eeMark: "2"` บวก `MENTION` และ `STICON_OWNERSHIP` เมื่อใช้
5. **ส่ง** ด้วย `line_send_sealed()`: `sendMessage` บน `/S4` ด้วย

   ```
   {1: reqSeq,
    2: {2: chat, 5: 0, 6: 0, 14: false, 15: contentType, 18: metadata,
        19: 0, 20: chunks,
        21: replyTo, 22: 3, 24: 1 (เฉพาะการตอบกลับ)}}
   ```

6. **อ่านคำตอบ**: รหัสข้อความใหม่อยู่ในฟิลด์ 4 และเวลาในฟิลด์ 5 ถ้าไม่มีรหัสจะได้ "Check the chat before resending" ข้อความอาจส่งถึงหรือไม่ถึงก็ได้ ไคลเอนต์จึงไม่ลองส่งซ้ำเอง

### อีโมจิ LINE ในข้อความ

UI แปลงอีโมจิแต่ละตัวในฉบับร่างเป็นช่วง ตำแหน่งนับเป็น **หน่วยรหัส UTF-16** เหมือนที่แอป LINE นับ (`utf16_units()` ใน `ui.c`) ใน payload ที่ปิดผนึก ทรัพยากรแต่ละตัวคือ

```json
{"S": 0, "E": 2, "productId": "670e0cce840a8236ddd4ee4c", "sticonId": "001",
 "version": 1, "resourceType": "STATIC"}
```

`S` และ `E` คือตำแหน่งเริ่มและจบ ข้อความในช่วงนั้นคือป้ายแทนของอีโมจิ ไคลเอนต์ที่ไม่มีรูปก็ยังแสดงสิ่งที่พอเข้าใจได้ `STICON_OWNERSHIP` ใน metadata แบบธรรมดาระบุรหัสผลิตภัณฑ์ที่ใช้ `emoji_ranges()` ตรวจทุกช่วงเทียบกับข้อความทั้งก่อนส่งและหลังรับ

### การเมนชัน

ในกลุ่ม `mentions` คือรายการ `{id, start, length}` ในหน่วย UTF-16 แต่ละตัวชี้ไปที่ `@ชื่อ` ในข้อความ `mention_metadata()` ตรวจแต่ละตัว (ไม่เกิน 20 ตัว ต้องเป็น MID `u…` และเริ่มด้วย `@`) แล้วสร้าง

```json
{"MENTIONEES": [{"S": "0", "E": "6", "M": "u…"}]}
```

เก็บเป็นค่า metadata `MENTION` **ข้อควรรู้:** metadata ไม่ได้เข้ารหัส เซิร์ฟเวอร์ของ LINE จึงเห็นว่าใครถูกเมนชันและอยู่ตรงไหน เหมือนกับแอป LINE เอง การพิมพ์ `@` ในกลุ่มหรือโอเพนแชทจะเรียก `mentionCandidates` (`line_group_members()` หรือ `line_square_search_mentionables()`) เพื่อแสดงเมนูป๊อปอัปแนะนำชื่อเหนือช่องพิมพ์ข้อความ

### การ์ดรายชื่อ การ์ดตำแหน่ง และการเล่นเสียงในแอป

- **การ์ดรายชื่อ** (`contentType = 13`) ดึง `contactMid` และ `contactName` จาก `contentMetadata` และแสดงเป็นการ์ดที่คลิกเพื่อเปิดการ์ดโปรไฟล์ได้ (`ui_profile_open()`)
- **การ์ดตำแหน่ง** (`contentType = 15`) ดึง `location: {title, address, lat, lon, phone}` จากฟิลด์ Thrift `11` และคลิกเปิดพิกัดบน OpenStreetMap ผ่าน `SDL_OpenURL()`
- **ข้อความเสียงและสติกเกอร์มีเสียง** เล่นภายในแอปผ่าน `ffplay` โดยส่งข้อมูลผ่านไฟล์หน่วยความจำปิดผนึก (`openAudio` และ `stickerSound` ซึ่งดึง `stickershop/v1/sticker/<id>/android/sticker_sound.m4a` พร้อมตรวจส่วนหัว ISO BMFF `ftyp`) ตัวเล่นรับเฉพาะรูปแบบเสียงจากไฟล์ในเครื่อง และใช้ตัวแยกสตรีม MOV สำหรับสติกเกอร์โดยปิดการโหลดแทร็กภายนอก

## รีแอ็กชันและการยกเลิกส่ง

`line_message_action()`

- **รีแอ็กชัน:** `react` บน `/S4` ด้วย `{1: {1: reqSeq, 2: รหัสข้อความ (i64), 3: {1: ชนิด}}}` ชนิด: 1 none (ลบ), 2 nice, 3 love, 4 fun, 5 amazing, 6 sad, 7 omg UI ใช้ป้าย Like, Love, Laugh, Amazing, Sad และ Surprised
- **ยกเลิกส่ง:** `unsendMessage` ด้วย `{1: reqSeq, 2: รหัสข้อความ}` worker อนุญาตเฉพาะข้อความของคุณเอง

เมื่อ LINE ยืนยันการถอนข้อความหรือส่ง operation 64 หรือ 65 Avernella จะแทนที่ข้อความหรือสติกเกอร์ด้วยป้าย **ข้อความถูกถอน** ที่กึ่งกลาง แคชของแอปจะลบเนื้อหาเดิมและเก็บเฉพาะรหัสแชท รหัสข้อความ และเวลาส่งเดิมถ้าทราบ โดยจัดเก็บจำกัดจำนวนและผูกกับบัญชีที่เข้าสู่ระบบเพื่อป้องกันไม่ให้ประวัติที่มาช้าแสดงเนื้อหาเดิมอีกครั้ง

## การแจ้งว่าอ่านแล้ว

`line_mark_read()` เรียก `sendChatChecked` บน `/S4` ด้วย `{1: reqSeq, 2: chat, 3: รหัสข้อความล่าสุด}` โดยไม่ใส่ session ID ซึ่งเป็นตัวเลือก เหมือนแอปเดสก์ท็อป และปฏิเสธแชต Keep Memo ของตัวเอง UI เป็นผู้ตัดสินว่าจะส่งเมื่อไร (ดู [ส่วนติดต่อผู้ใช้](ui.md)) และ worker รักษาเป้าหมายของการแจ้งอ่านไม่ให้ถอยหลัง (`read_acks`, `unread_heads`) การยืนยันที่มาช้าจึงไม่ทำให้การแจ้งอ่านย้อนกลับ

## การส่งต่อ

`forwardMessage` รับรหัสข้อความจากแชตที่เปิดอยู่และแชตปลายทาง `forward_message()` ใน `main.c` รองรับทั้งข้อความ ไฟล์แนบ สติกเกอร์ ตำแหน่ง และการ์ดรายชื่อ ทั้งในแชตทั่วไปและโอเพนแชท

- **ข้อความ** ส่งใหม่ด้วย `line_forward_text()` (หรือ `line_square_send_text()`): เปิดแล้วปิดผนึกใหม่สำหรับแชตปลายทาง โดยคงอีโมจิ LINE ไว้
- **ไฟล์แนบ** ถูกดาวน์โหลด ถอดรหัส แล้วอัปโหลดใหม่ด้วยกุญแจใหม่สำหรับปลายทาง (`line_forward_attachment()` ใน `media.c`) กุญแจไม่เคยถูกใช้ร่วมระหว่างแชต
- **สติกเกอร์ ตำแหน่ง และการ์ดรายชื่อ** ส่งต่อด้วย `line_forward_sticker()`, `line_forward_location()` และ `line_forward_contact()` (รวมถึง `line_square_forward_*()`) โดยคงข้อมูล metadata ของสติกเกอร์ (`STKID`/`STKPKGID`/`STKVER`/`STKOPT`/`STKHASH`) พิกัดตำแหน่ง (`11:obj` พร้อมฟิลด์ `double` มาตรฐาน IEEE 754) หรือ MID/ชื่อของการ์ดรายชื่อไว้ครบถ้วน

## ประกาศ

ประกาศคือโน้ตที่ปักไว้ด้านบนของแชต เก็บบนเซิร์ฟเวอร์ของ LINE **นอก Letter Sealing** UI จึงเตือนก่อนสร้าง

| การกระทำ | RPC บน `/S4` | อาร์กิวเมนต์ |
| -------- | ------------ | ------------ |
| ดูรายการ | `getChatRoomAnnouncements` | `{2: chat}` แต่ละรายการ: 1 รหัส, 3 เนื้อหา (ฟิลด์ 2 คือข้อความ), 4 ผู้สร้าง, 6 สิทธิ์ (0 ใครก็ลบได้, 1 เฉพาะผู้สร้าง) |
| สร้าง | `createChatRoomAnnouncement` | `{1: reqSeq, 2: chat, 3: 0, 4: {1: 5, 2: ข้อความ, 3: "line://nv/chatMsg?chatId=<chat>&messageId=<id>"}}` |
| ลบ | `removeChatRoomAnnouncement` | `{1: reqSeq, 2: chat, 3: รหัสประกาศ (i64)}` |

OpenChat ใช้ `getSquareChatAnnouncements`, `createSquareChatAnnouncement` และ `deleteSquareChatAnnouncement` บน SquareService แอปอ่านรหัสข้อความต้นทางจากเนื้อหาในประกาศ หรือจากลิงก์ข้อความ LINE ที่ตรงกับห้องในแชตทั่วไป Talk operation 30 และ Square event 37 จะอัปเดตแบนเนอร์ของบทสนทนาที่เปิดอยู่

## การค้นหา

แชตส่วนตัวไม่มี API ค้นหาฝั่งเซิร์ฟเวอร์ การค้นหาจึงทำบนหน้าที่ worker ดึงมา

- **ในแชตเดียว** (`findMessages`, `find_messages()` ใน `main.c`): ค้นหน้าของแชตที่เปิดอยู่ จากใหม่ไปเก่า โดยไม่สนตัวพิมพ์เล็กใหญ่ (`search_text()`) และค้นต่อไปยังหน้าเก่าได้ โดยจำขอบเขตไว้ระหว่างการเรียก
- **ข้ามแชต** (`findAllMessages`, `find_all_messages()`): ใช้ข้อความล่าสุด 50 ข้อความของแชตไม่เกินหกแชตต่อการเรียก ภายในงบเวลา 350 ms และค้นต่อจากจุดที่หยุดในการเรียกครั้งถัดไป แชตที่มีหน้าล่าสุดอยู่ในแคชประวัติและยังไม่ล้าสมัยจะค้นจากหน่วยความจำ โดยไม่ต้องขอจาก LINE อีก

## เรื่องที่ต้องจำไว้

- **จองลำดับคำขอก่อน RPC ที่เปลี่ยนสถานะเสมอ** ดู [การลงชื่อเข้าใช้](sign-in.md)
- **อย่าเชื่อสำเนาข้อความของ UI** ให้ค้น Message ดิบใน `w->messages` จากรหัส
- **metadata เป็นสาธารณะ chunk เป็นส่วนตัว** ข้อมูลลับต้องอยู่ใน payload ที่ปิดผนึก ไม่ใช่ใน `contentMetadata`
- **ตำแหน่งของอีโมจิและเมนชันเป็นหน่วย UTF-16** ไม่ใช่ไบต์หรือจำนวนตัวอักษร
