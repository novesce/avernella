# ส่วนติดต่อผู้ใช้

[สารบัญ](README.md) · ก่อนหน้า: [สถาปัตยกรรม](architecture.md) · ถัดไป: [พื้นฐานโปรโตคอล LINE](protocol-basics.md)

ทุกอย่างในหน้านี้ทำงานใน **โปรเซส UI** ซึ่งไม่เคยคุยกับ LINE โดยตรง แต่จะขอผ่าน worker (ดู [สถาปัตยกรรม](architecture.md)) แล้ววาดสิ่งที่ได้กลับมา

## ลูปหลัก

`line_ui()` ใน [`ui.c`](../../src/ui.c) ตั้งค่า SDL แล้ววนลูปจนกว่า `ui.quitting` จะเป็นจริง

1. **ถึงเวลาวาดเฟรมหรือยัง?** `frame_wait()` ถามนาฬิกาเฟรม ([`ui_motion.c`](../../src/ui_motion.c)) ว่าเหลือเวลาเท่าไรถึงเฟรมถัดไป จะต้องวาดเฟรมเมื่อมีอะไร dirty (`ui.dirty`, `ui.video_dirty`) มีแอนิเมชันกำลังเล่น กำลังเลื่อนแบบนุ่มนวล หรืออีโมจิเคลื่อนไหวต้องเปลี่ยนภาพ ถ้าไม่มีอะไรต้องวาด จะรอไม่มีกำหนด ถ้าหน้าต่างถูกซ่อนหรือย่อ จะไม่วาดอะไรเลย แต่ยังรับอีเวนต์อยู่
2. **วาด** ถ้าถึงเวลา การวาดใหม่มีสามขนาด
   - `ui_draw()` วาดใหม่ทั้งหน้าต่าง: เมื่อมีอะไร dirty ระหว่างแอนิเมชัน หรือเมื่อทั้งรายการแชตและประวัติเลื่อนพร้อมกัน
   - `ui_draw_region(rect)` วาดใหม่เฉพาะรายการแชตหรือเฉพาะบทสนทนา เมื่อมีแค่ส่วนนั้นที่เลื่อน
   - `ui_draw_video()` นำเสนอวิดีโอคอลใหม่โดยไม่วาดส่วนอื่นใหม่
3. **รออีเวนต์** ด้วย `SDL_WaitEventTimeout(wait_ms)` (หรือ `SDL_WaitEvent` เมื่อรอไม่มีกำหนด) อินพุตและแพ็กเก็ตจาก worker จะปลุกทันที
4. **จัดการอีเวนต์** ผ่าน `event()` จัดการได้สูงสุด 64 อีเวนต์ก่อนวาดอีกครั้ง การขยับเมาส์ต่อเนื่องจึงไม่ทำให้หน้าจอค้าง

จังหวะเฟรมเป็นไปตามอัตรารีเฟรชของจอ (`display_rate()` อ่านจาก SDL) และถูกจำกัดด้วย `AVERNELLA_MAX_FPS` เวลากำหนดทุกตัวใช้นาฬิกาแบบ monotonic

### อีเวนต์ไปที่ไหน

`event()` ใน `ui.c` ส่งต่ออีเวนต์ของ SDL ดังนี้

- **แพ็กเก็ตจาก worker** (SDL user event `wire.packet_event`) ไปที่ `handle_packet()`
- **เฟรมวิดีโอคอล** (`wire.preview_event`) ไปที่ `ui_media_preview_frame()`
- **อินพุต** ไปที่ overlay ที่เปิดอยู่ก่อน โมดูลฟีเจอร์แต่ละตัวมี `ui_<module>_active()` และ `ui_<module>_event()` ถ้าโมดูลเปิดอยู่ จะได้อีเวนต์ก่อนและคืน `TRUE` เมื่อใช้อีเวนต์นั้นแล้ว ลำดับใน `event()` เป็นตัวกำหนดว่า overlay ไหนอยู่บนสุด ถ้าไม่มี overlay ไหนรับ `key()` และ `click()` ใน `ui.c` จะจัดการหน้าต่างหลัก

### สถานะของส่วนติดต่อ

struct เดียวชื่อ `Interface ui` (ประกาศใน [`ui_private.h`](../../src/ui_private.h)) เก็บสถานะของหน้าต่างหลัก: ขนาดหน้าต่าง รายการแชตปัจจุบัน (`ui.chats` อาร์เรย์ JSON จาก worker) และดัชนีที่มองเห็นหลังกรอง (`ui.visible`) แชตที่เลือก (`ui.selected`) ประวัติของมัน (`ui.history`) ช่องแก้ไขข้อความ (ช่องค้นหา ช่องพิมพ์ข้อความ ช่องลงชื่อเข้าใช้) ฉบับร่างของแต่ละแชต (`ui.drafts`) ตำแหน่งการเลื่อน สี่เหลี่ยมของปุ่มต่าง ๆ (กรอกโดย `ui_layout()`) และแฟล็กความสามารถที่ worker ส่งมาตอนลงชื่อเข้าใช้ (`ui.photos`, `ui.calls`, `ui.video_calls` เป็นต้น)

โมดูลฟีเจอร์เก็บสถานะของตัวเองใน struct แบบ `static` ภายในไฟล์ `.c` ของมัน มีแค่เธรดหลักที่แตะได้

**โฟกัส** `ui.focus` เป็นค่าหนึ่งใน `Focus` ของ `ui_private.h` (`F_SEARCH`, `F_LIST`, `F_MESSAGE`, `F_SEND`…) ปุ่ม Tab และ Shift+Tab เลื่อนโฟกัสใน `tab_focus()`

**โหมดกะทัดรัด** เมื่อหน้าต่างกว้าง 640 พิกเซลตรรกะหรือน้อยกว่า (`ui_compact()`) จะแสดงรายการแชต *หรือ* บทสนทนาอย่างใดอย่างหนึ่ง และ Escape พากลับไปรายการ `ui_chat_visible()` และ `ui_list_visible()` บอกว่ากำลังแสดงอะไร

**ช่องแก้ไขข้อความ** `Editor` คือ `GString` พร้อมเคอร์เซอร์และจุดยึดการเลือกเป็น offset แบบไบต์ของ UTF-8 `ui_edit_key()` และ `ui_insert()` ใน `ui.c` ทำการแก้ไข การกระโดดทีละคำ การเลือก และคลิปบอร์ด ข้อความถูกวัดด้วย Pango ภาษาไทย สระและวรรณยุกต์ และอีโมจิจึงทำงานถูกต้อง

## ไปป์ไลน์การวาด

การวาดมีสองครึ่ง: **rasterize** พิกเซลบน CPU ด้วย Cairo และ Pango กับ **นำเสนอ** ผ่าน GPU หรือ SDL

### การ rasterize

[`ui_draw.c`](../../src/ui_draw.c) วาดทุกอย่างลงภาพพื้นหลังภาพเดียวขนาดเท่าหน้าต่างในหน่วยพิกเซล *จริงของอุปกรณ์* (ขนาดตรรกะ × สเกลของจอ) เก็บใน `ui.buffer` ซึ่งเป็น `SDL_Surface` แบบ `RGB888` Cairo context `cr` ห่อพื้นผิวนั้นไว้ และ Pango จัดวางข้อความลงไป

- **พิกัดตรรกะ** การจัดวางและอินพุตใช้พิกเซลตรรกะ `ui_pixel_scale()` ให้อัตราส่วนพิกเซลของอุปกรณ์ และ Cairo ถูกสเกลครั้งเดียว ตัวอักษรและเส้นจึงคมที่ความละเอียดจริงบนจอ HiDPI
- **จัดวางก่อน** `ui_layout()` คำนวณทุกสี่เหลี่ยม (rail รายการแชต หัวแชต บทสนทนา ช่องพิมพ์ ปุ่ม) ตามขนาดหน้าต่างและธีมปัจจุบัน ทั้งการวาดและการตรวจว่าคลิกโดนอะไรใช้สี่เหลี่ยมชุดเดียวกัน
- **แคช** ป้ายสั้น ๆ และตัวควบคุมเก็บ Pango layout ไว้ในตารางขนาดคงที่ (`label_layout()`) โดยใช้ข้อความ ขนาด น้ำหนัก ความกว้าง และการจัดแนวเป็นคีย์ ฟองข้อความถูกจัดวางครั้งเดียวต่อประวัติหนึ่งชุด (`prepare_bubbles()`) ลงอาร์เรย์ `struct message_layout` การเลื่อนจึงไม่ต้องจัดรูปข้อความใหม่
- **ฟังก์ชันช่วยวาด** โมดูลอื่นวาดผ่านฟังก์ชันที่ประกาศใน `ui_private.h` เช่น `ui_draw_box()`, `ui_draw_rounded()`, `ui_draw_label()`, `ui_draw_button()`, `ui_draw_icon()`, `ui_draw_avatar()`, `ui_draw_switch()`, `ui_draw_tooltip()`, `ui_draw_image()`, `ui_scrim()` เป็นต้น
- **รูปภาพ** ถอดรหัสในเธรดถอดรหัสของ [`ui_media.c`](../../src/ui_media.c) (`decode_image()`) ซึ่งสร้าง Cairo image surface [`ui_pixels.c`](../../src/ui_pixels.c) ทำ premultiply alpha ในลูปที่ GCC vectorize ได้ (`-O3`) [`ui_apng.c`](../../src/ui_apng.c) ถอดรหัสเฟรมของ PNG เคลื่อนไหวและบอกลูปว่าเฟรมถัดไปต้องแสดงเมื่อไร

### การนำเสนอ

มีเส้นทางการนำเสนอสามแบบ แอปเลือกแบบแรกที่ใช้ได้แล้วจำไว้

1. **โมดูล Vulkan แบบเนทีฟ** (`avernella-vulkan.so` ซอร์สอยู่ใน [`src/render/`](../../src/render)) [`ui_gpu.c`](../../src/ui_gpu.c) หาไฟล์นี้ข้าง ๆ โปรแกรมหรือใน `../lib/avernella` โหลดด้วย `dlopen` และดึงสัญลักษณ์เดียวคือ `avernella_gpu_v1` ซึ่งเป็น `struct gpu_backend` ที่มี `open`, `close`, `size` และ `draw` (ดู [`gpu_backend.h`](../../src/render/gpu_backend.h)) หน้าต่างถูกสร้างด้วย `SDL_WINDOW_VULKAN` ทุกเฟรม UI ส่ง `struct gpu_scene` ([`gpu_scene.h`](../../src/render/gpu_scene.h)) ให้โมดูล ได้แก่ พอยน์เตอร์ไปยังพิกเซลของ Cairo สี่เหลี่ยมที่เปลี่ยน (damage) สี่เหลี่ยมที่ต้องอัปโหลดได้ถึง 8 ช่อง การคัดลอกจาก texture ขึ้นจอได้ถึง 8 ช่อง และระนาบวิดีโอได้ถึงสามชุด (กล้องอีกฝ่าย กล้องตัวเอง หน้าจอที่แชร์)
2. **ตัววาด Vulkan ของ SDL** ถ้าไม่มีโมดูลหรือโมดูลล้มเหลว `ui_draw_init()` จะขอไดรเวอร์ `vulkan` ของ SDL และเก็บ canvas ไว้ใน `SDL_Texture`
3. **พื้นผิวหน้าต่างของ SDL** ถ้าไม่มี Vulkan ภาพพื้นหลังจะถูกคัดลอกลงพื้นผิวหน้าต่าง บน Wayland ยังใช้การนำเสนอของ SDL

`LINE_RENDER_LOG=1` พิมพ์ว่าเลือกเส้นทางไหน `LINE_DISABLE_GPU=1` บังคับเส้นทางที่ 3 และ `AVERNELLA_VULKAN=sdl` ข้ามเส้นทางที่ 1

#### ข้างในโมดูล Vulkan

โมดูล ([`vk_ctx.c`](../../src/render/vk_ctx.c), [`vk_frame.c`](../../src/render/vk_frame.c), [`vk_canvas.c`](../../src/render/vk_canvas.c), [`vk_tex.c`](../../src/render/vk_tex.c), [`vk_present.c`](../../src/render/vk_present.c), [`vk_desc_buffer.c`](../../src/render/vk_desc_buffer.c)) ตั้งใจให้ทำงานน้อยมาก

- เลือกอุปกรณ์ที่นำเสนอขึ้นหน้าต่างได้และตรวจคุณสมบัติของมัน เลือกใช้ **descriptor heap** (`VK_EXT_descriptor_heap`) ก่อน และถอยไปใช้ **descriptor buffer** บน Vulkan 1.3 `AVERNELLA_VK_DESCRIPTORS=buffer` บังคับแบบหลัง
- graphics pipeline เดียวกับ shader คู่เดียวแบบ "uber" ([`ui_uber.vert`](../../src/render/ui_uber.vert), [`ui_uber.frag`](../../src/render/ui_uber.frag)) ที่คอมไพล์เป็น SPIR-V ตอน build วาดทุก primitive primitive หนึ่งตัว (`struct ui_prim` ใน [`ui_batch.h`](../../src/render/ui_batch.h) ขนาด 64 ไบต์) เป็นได้ทั้งสี่เหลี่ยม glyph รูป dma-buf ตัว canvas หรือเฟรมวิดีโอ I420 ใช้สี่ vertex ต่อสี่เหลี่ยม ตัดขอบก่อน rasterize และมีทางลัดสำหรับ canvas ทึบ หน้ากาก glyph และวิดีโอ I420
- canvas ของ Cairo อยู่ใน texture บนอุปกรณ์ อัปโหลดเฉพาะส่วนที่เปลี่ยน ใช้ frame slot สองช่องที่นำหน่วยความจำอัปโหลดซึ่งแมปไว้มาใช้ซ้ำ และใช้ barrier ของ Synchronization2 เพื่อจัดลำดับการโอนข้อมูลกับการอ่านใน shader
- วิดีโอคอลถูกแปลงจาก I420 เป็น RGB ใน shader CPU จึงไม่ต้องแปลงเฟรมวิดีโอเลย
- บนไดรเวอร์ที่มี `VK_KHR_incremental_present` จะบอก compositor ว่าส่วนไหนของหน้าต่างเปลี่ยน

### Damage: วาดเฉพาะส่วนที่เปลี่ยน

`draw_frame()` ใน `ui_draw.c` ถูกเรียกพร้อมบริเวณที่ต้องวาด หรือ `NULL` สำหรับทั้งหน้าต่าง มันตัดขอบ Cairo ให้อยู่ในบริเวณนั้นและวาดเฉพาะสิ่งที่ตัดกับบริเวณ ตัวนำเสนอจึงอัปโหลดแค่สี่เหลี่ยมนั้น เมื่อมีแค่วิดีโอเปลี่ยน `ui_draw_video()` จะนำเสนอโดยไม่ต้องใช้ Cairo เลย

### การนำภาพเดิมกลับมาใช้ตอนเลื่อน

การเลื่อนบทสนทนาคือการวาดใหม่ที่เกิดบ่อยที่สุด จึงมีเส้นทางพิเศษ เมื่อประวัติใช้ซ้ำได้ (`reusable_history()`) texture ของ canvas จะเก็บพื้นที่บทสนทนาเป็น **บัฟเฟอร์วงกลม**: `history_scroll.origin` บอกว่าแถวไหนของ texture คือบรรทัดแรกที่มองเห็น เมื่อเลื่อนไป *dy* พิกเซล

1. ขยับ origin ไป *dy* (`advance_history()`)
2. วาดใหม่เฉพาะแถวที่เพิ่งโผล่ บวกแถบกันขอบสองพิกเซล และแถวข้อความที่สีไฮไลต์ตอนเมาส์ชี้เปลี่ยน (`history_damage.bands` ที่ `merge_history_bands()` รวมเข้าด้วยกัน)
3. อัปโหลดเฉพาะแถบเหล่านั้น (`history_uploads()`)
4. วาดบทสนทนาด้วยการคัดลอก texture ไม่เกินสองครั้งเพื่อคลายวงกลม (`ui_scroll_slices()` และ `ui_scroll_quads()` ใน [`ui_gpu_scroll.c`](../../src/ui_gpu_scroll.c))

การใช้ซ้ำจะถูกปิดทุกครั้งที่แถวที่มองเห็นอาจวาดสิ่งที่เปลี่ยนเองได้: รูป วิดีโอ rich message การ์ด Flex อีโมจิ LINE overlay แอนิเมชัน หน้าจอการโทร หรือประวัติที่ติดอยู่ด้านล่าง ถ้าสงสัยเมื่อไรก็วาดใหม่ทั้งหมด ซึ่งถูกต้องเสมอ `tests/ui_scroll_scene.c` และ `make bench` พร้อม `LINE_BENCH_DAMAGE=1` ตรวจว่าเฟรมที่ใช้ซ้ำตรงกับการวาดใหม่ทั้งหมด

### แอนิเมชันและโหมดลดการเคลื่อนไหว

[`ui_motion.c`](../../src/ui_motion.c) มีนาฬิกาเฟรม (`UiFrameClock`) การเลื่อนแบบนุ่มนวล (`UiScroll` ซึ่งสุ่มค่าทุกเฟรม) และสวิตช์ลดการเคลื่อนไหว `ui_reduce_motion()` เป็นจริงเมื่อ

- การตั้งค่าของบัญชีกำหนดไว้ (**User Settings → Appearance**) เก็บเป็น `motion` ในไฟล์การตั้งค่าแชต หรือ
- การตั้งค่าเลือกให้ทำตามเดสก์ท็อป และ `org.gnome.desktop.interface enable-animations` ของ GNOME ปิดอยู่ หรือ
- `LINE_REDUCE_MOTION=1`

เมื่อลดการเคลื่อนไหว การเลื่อนจะกระโดดทันที การเปลี่ยนผ่านจบทันที และรูปเคลื่อนไหวแสดงเป็นภาพนิ่ง `ui_draw.c` มี "แทร็กคุณสมบัติ" เล็ก ๆ (`struct color_transition`, `struct slide_transition`) สำหรับการจางของ hover และการเลื่อน และ `ui_animation_deadline()` บอกว่าแอนิเมชันถัดไปต้องการเฟรมเมื่อไร

การเคลื่อนไหวมีกฎไม่กี่ข้อ อินพุตมีผลในเฟรมที่มันมาถึง แอนิเมชันเพียงแสดงการเปลี่ยนแปลงนั้น การเคลื่อนไหวทุกแบบสั้น (40–250 ms) เริ่มเร็วแล้วค่อย ๆ ช้าลง และขัดจังหวะได้ เมื่อเปลี่ยนเป้าหมายจะเริ่มจากค่าที่สุ่มได้ในขณะนั้น จึงไม่มีอะไรกระโดดหรือต่อคิว เมื่อการเคลื่อนไหวสุดท้ายหยุด deadline จะกลับเป็นศูนย์และลูปจะรออินพุตอีกครั้ง สิ่งที่เคลื่อนไหวในตอนนี้:

| การโต้ตอบ | การเคลื่อนไหว | อยู่ที่ |
| --- | --- | --- |
| ล้อเมาส์ ทัชแพด Page Up/Down | ease-out 120 ms ต่อแรงเลื่อนแต่ละครั้ง หลายจังหวะรวมกันได้ และเปลี่ยนทิศได้ทันที | `ui_scroll_by()` |
| ปุ่ม Up/Down ในรายการแชต | รายการค่อย ๆ เลื่อนแถวที่เลือกเข้ามาในจอ ถ้ากดค้างจะเปลี่ยนเป้าหมายจากตำแหน่งที่รายการกำลังไป | `ui_scroll_to()`, `highlight()` ใน `ui.c` |
| hover การเลือก โฟกัส | สีค่อย ๆ เปลี่ยน 110–150 ms | `track_strength()` |
| การกดปุ่ม | กดลง 40 ms ปล่อย 145 ms และเด้งเกินเล็กน้อยหนึ่งครั้ง (`ui_press_depth()`) ใช้กับปุ่มคำสั่ง ปุ่มบนหัวแชตและปุ่มโทร rail และปุ่มแนบไฟล์ อีโมจิ และ Send ในช่องพิมพ์ | `button_depth()` |
| ข้อความใหม่ขณะประวัติแชตติดขอบล่าง | ประวัติค่อย ๆ เลื่อนขึ้นใน 180 ms แทนการกระโดด ถ้ามาหลายข้อความติดกันจะบวกเข้ากับระยะที่เหลือ (`UiGlide`) | `follow_bottom()` |
| การเปิดแชต | หน้าแรกค่อย ๆ ปรากฏและลอยขึ้น 6 px ใน 140 ms | `reveal_history()` |
| สลับแผงในโหมดแคบ กล่องโต้ตอบ | เลื่อน 10 px / 8 px แล้วค่อย ๆ หยุด (`ui_settle()`) ฉากหลังค่อย ๆ จาง | `slide()` |

การเลื่อนรับข้อความใหม่จะทำงานเฉพาะเมื่อผู้อ่านอยู่ที่ขอบล่าง และแถวที่ใหม่ที่สุดก่อนหน้ายังอยู่โดยมีแถวใหม่ต่อท้าย การโหลดหน้าเก่ากว่า การปรับขนาดหน้าต่าง การเปลี่ยนธีม หรือชุดข้อความที่สูงกว่าพื้นที่แสดงผลจะกระโดดไปทันที ระหว่างที่การเลื่อนหรือการจางทำงาน `ui_draw_animation()` จะวาดใหม่เฉพาะพื้นที่บทสนทนา และ `reusable_history()` จะปิดการนำภาพเดิมกลับมาใช้ hover ของแถวข้อความในประวัติยังเปลี่ยนทันที เพื่อให้การนำภาพเดิมกลับมาใช้ตอนเลื่อนยังทำงานขณะเมาส์วางอยู่บนประวัติ เมื่อลดการเคลื่อนไหว ทุกแถวในตารางจะถึงสถานะสุดท้ายในเฟรมเดียวกัน

## ธีม

[`ui_theme.c`](../../src/ui_theme.c) และ [`ui_theme.h`](../../src/ui_theme.h) กำหนดรูปแบบหน้าจอสองแบบที่ใช้ชุดสีร่วมกัน

| ธีม | หน้าตา | ความต่างในโค้ด |
| --- | ------ | -------------- |
| **LINE** (ค่าเริ่มต้น) | ทำตามแอป LINE บนเดสก์ท็อป: แถบนำทางแคบที่มีแท็บ Friends และ Chats และปุ่มบัญชีอยู่ด้านล่าง แถวแชตสูง 68 พิกเซลแสดงข้อความล่าสุด เวลา และจำนวนที่ยังไม่อ่าน ฟองข้อความขาเข้าอยู่ซ้าย ข้อความของคุณอยู่ขวา และแผงพิมพ์ที่มีปุ่มอีโมจิ ไฟล์ และ **Send** | `ui_theme_is_line()` เป็นจริง `line_bar()`, `line_chat_row()` และ `line_composer()` ใน `ui_draw.c` เป็นผู้วาด `ui_profile_place()` ย้ายปุ่มโปรไฟล์ Inbox และการตั้งค่าเข้าไปในแถบ |
| **Avernella** | รูปแบบกะทัดรัด มี rail แบบเซิร์ฟเวอร์ (แชตที่ยังไม่อ่านปักเป็นปุ่มกลม) แถวแชตสูง 44 พิกเซล ข้อความจัดกลุ่มตามผู้ส่ง แผงผู้ใช้ที่มุมซ้ายล่าง และแถบพิมพ์มนแถบเดียว | `server_rail()`, `chats_panel()`, `user_panel()` และ `composer()` ใน `ui_draw.c` |

ทั้งสองใช้พื้นผิวสีพลัมเข้มกับสีเน้นชมพูสดของ Avernella (`UI_BG`, `UI_PANEL`, `UI_ACCENT` และค่าอื่นใน `ui_theme.h`) ธีม LINE แปลงสีเขียวของ LINE เป็นสีชมพู (`UI_BUBBLE_OUT`, `UI_NAV_ACTIVE`) สีเขียนเป็นจำนวนเต็มรูปแบบ `0xRRGGBB`

ธีมที่เลือกถูกอ่านครั้งเดียวตอนเริ่ม (`ui_theme_init()`) จาก `~/.config/avernella/layout`: ไฟล์ที่มีข้อความ `avernella\n` พอดีหมายถึงธีม Avernella ค่าอื่นหมายถึง LINE `ui_theme_toggle()` เขียนไฟล์แบบ atomic แล้วสลับธีม จากนั้น `ui_theme_changed()` ใน `ui.c` ปรับตำแหน่งการเลื่อนให้เข้ากับความสูงแถวใหม่ (`ui_chat_row_height()`) และจัดวางใหม่

เมื่อเพิ่มพื้นผิวใหม่ ให้ใช้ค่าคงที่ของชุดสีแทนการใส่ตัวเลขสีเอง และทดสอบทั้งสองธีม

## ภาษาของส่วนติดต่อ

ส่วนติดต่อแปลได้ผ่าน [`src/ui_lang.c`](../../src/ui_lang.c) รองรับ 17 ภาษา (`enum ui_language` ใน `ui_lang.h`) ข้อความภาษาอังกฤษที่ผู้ใช้เห็นในซอร์สคือคีย์ ถูกห่อด้วย `_()` (หรือ `N_()` ในตารางแบบ static ซึ่งแปลตอนวาด) และแต่ละภาษามีตารางคู่ `{ ภาษาอังกฤษ, คำแปล }` ใน `src/ui_lang_<tag>.c` ถ้าไม่มีคู่ใดจะใช้ภาษาอังกฤษแทน เลือกภาษาได้ที่ **User Settings → Appearance** และบันทึกไว้ใน `~/.config/avernella/language` ถ้ายังไม่เคยเลือกจะใช้ภาษาตาม locale ของเดสก์ท็อป การเพิ่มข้อความใหม่ทำได้โดยห่อด้วย `_()` แล้วเพิ่มคู่ลงในทุกตาราง `tests/ui_lang.c` ตรวจว่าคำแปลยังมีตัวแปลงรูปแบบของ printf ครบเหมือนต้นฉบับ

## ฟีเจอร์และไฟล์ที่เขียน

โมดูลฟีเจอร์ทุกตัวใช้รูปแบบเดียวกัน รู้จักตัวหนึ่งก็เข้าใจทุกตัว

| ฟังก์ชัน | หน้าที่ |
| -------- | ------- |
| `ui_<m>_open()` / `_show()` | เปิดหน้าจอหรือ overlay |
| `ui_<m>_active()` | เปิดอยู่หรือเปล่า |
| `ui_<m>_event(SDL_Event *)` | จัดการอินพุตระหว่างเปิดอยู่ คืน `TRUE` ถ้าใช้อีเวนต์นั้นแล้ว |
| `ui_<m>_reply(method, tag, result, error)` | จัดการคำตอบจาก worker คืน `TRUE` ถ้าเมธอดนั้นเป็นของโมดูลนี้ |
| `ui_<m>_draw()` | วาด |
| `ui_<m>_resume_input()` | คืนการรับข้อความเมื่อได้โฟกัสกลับมา |
| `ui_<m>_reset()` | ลืมทุกอย่าง ตอนออกจากระบบ |

### หน้าลงชื่อเข้าใช้

`sign_in()` และ `layout_sign_in()` ใน `ui_draw.c` เป็นผู้วาด `login()`, `toggle_sign_in()`, `start_password_worker()`, `retry_login()` และ `reset_login()` ใน `ui.c` เป็นผู้ควบคุม QR code มาในอีเวนต์ `qr` และเข้ารหัสด้วย libqrencode อีเวนต์ `pin` จะแทนที่มันด้วยตัวเลขให้พิมพ์บนโทรศัพท์ ช่องรหัสผ่านถูกปิดบัง (`password_mask()`) และบัฟเฟอร์ถูกล้างหลังใช้ (`clear_password()`) ภาพต้อนรับมาจาก [`ui_logo.c`](../../src/ui_logo.c)

### รายการแชต

- **การวาด:** `chats_panel()` และ `line_chat_row()` ใน `ui_draw.c` เวลาที่แสดงทำตามกฎของ LINE (`list_stamp()`: เวลาถ้าเป็นวันนี้ ตามด้วย "Yesterday" ชื่อวัน แล้วเป็นวันที่) ข้อความล่าสุดแสดงเฉพาะแชตที่เปิดในเซสชันนี้ เพราะ RPC รายการแชตส่งมาแค่รหัสข้อความ (`remember_preview()`)
- **ข้อมูล:** `refresh()` ส่ง `chats` และ `show_chats()` แทนที่ `ui.chats` `chat_message()` ขยับแถวเดียวเมื่อมีข้อความใหม่โดยไม่ต้องโหลดใหม่ทั้งหมด
- **การกรอง:** พิมพ์ในช่องค้นหา (Ctrl+F) เพื่อกรองตามชื่อ (`ui_refilter_chats()`)
- **โฟลเดอร์และหมุด:** [`ui_chat_lists.c`](../../src/ui_chat_lists.c) วาดตัวเลือกโฟลเดอร์และเมนู และ [`chat_lists.c`](../../src/chat_lists.c) เก็บโฟลเดอร์ หมุด การปิดเสียง และปุ่มลัดของแต่ละบัญชี คลิกขวาที่แชตเพื่อปักหมุด ปิดเสียง หรือเพิ่มเข้าโฟลเดอร์
- **ป้ายยังไม่อ่านและการแจ้งอ่าน:** ดูหัวข้อการแจ้งว่าอ่านแล้วด้านล่าง

### บทสนทนา

- **ประวัติ:** `prepare_bubbles()` จัดวางข้อความและ `message_rows()` วาด พร้อมการจัดกลุ่มตามผู้ส่ง ตัวคั่นวัน และรีแอ็กชัน หน้าแรกคือข้อความล่าสุด 50 ข้อความ "Earlier messages" ส่ง `olderHistory` และ "Back to latest" พากลับ (`history_page()` ใน `ui.c`)
- **ช่องพิมพ์:** `line_composer()` หรือ `composer()` ใน `ui_draw.c` Enter คือส่ง (`send_message()`) ฉบับร่างเก็บแยกตามแชตใน `ui.drafts` ตลอดที่แอปเปิดอยู่
- **เมนูข้อความ:** คลิกขวาที่ข้อความ `actions()` ใน `ui_media.c` สร้างรายการสำหรับข้อความนั้น: ตอบกลับ คัดลอก รีแอ็กชัน ดูรูป คัดลอกรูป เล่นวิดีโอ บันทึก ส่งต่อ ประกาศ เมนชันผู้ส่ง (ในกลุ่ม) ยกเลิกส่ง (ข้อความของตัวเอง) `menu_action()` เป็นผู้ทำ
- **การตอบกลับ:** เลือก Reply แล้ว `ui.reply_id` จะถูกตั้งและแสดงเหนือช่องพิมพ์ Escape ยกเลิก
- **การเมนชัน:** "Mention sender" แทรก `@ชื่อ` ด้วย `ui_mention_member()` `ui.c` ติดตามช่วงไบต์ของแต่ละเมนชันขณะแก้ฉบับร่าง (`edit_mentions()`) และแปลงเป็นช่วง UTF-16 ตอนส่ง (`mention_ranges()`)
- **รีแอ็กชัน:** ถูกใจ รัก ขำ ทึ่ง เศร้า ตกใจ จำนวนแสดงใต้ฟองข้อความ
- **ข้อความที่อ่านไม่ได้:** ข้อความที่ปิดผนึกด้วยกุญแจที่อุปกรณ์นี้ไม่มี จะแสดงว่า "[Letter Sealing key missing on this device]"

### อีโมจิ LINE และสติกเกอร์

[`ui_emoji.c`](../../src/ui_emoji.c) คือตัวเลือก (Ctrl+E หรือปุ่มหน้ายิ้ม) มีแท็บอีโมจิซึ่งใช้ `emojiCatalog` ของ worker (ชุดสาธารณะ 45 ชุดจาก `emoji_pack_index.inc` บวกชุดที่บัญชีเป็นเจ้าของ) และแท็บสติกเกอร์ซึ่งใช้ `stickerCatalog` อีโมจิที่เลือกถูกแทรกในฉบับร่างเป็นโทเค็นแทนที่ และ `ui_emoji_export()` แปลงฉบับร่างเป็นข้อความกับช่วง `emojis` ตอนส่ง ในประวัติ `ui_emoji_shape_history()` แทนช่วงอีโมจิด้วยรูปในบรรทัดผ่าน attribute ของ Pango ภาพขอผ่านคำขอ `emoji` และ `sticker` และ PNG เคลื่อนไหวเล่นผ่าน `ui_apng.c`

### ไฟล์แนบ รูป วิดีโอ ภาพหน้าจอ

ทั้งหมดอยู่ใน [`ui_media.c`](../../src/ui_media.c)

- **เลือกไฟล์:** **+** หรือ Ctrl+O เปิดตัวเลือกไฟล์ในตัว (`open_picker()`, `directory()`) หรือลากไฟล์มาวางบนหน้าต่าง `prepare_attachment()` ตัดสินว่าเป็นรูป วิดีโอ เสียง หรือไฟล์ และหน้าตัวอย่างจะส่ง `sendPhoto` หรือ `sendFile`
- **การวาง:** Ctrl+V ในช่องพิมพ์เรียก `ui_media_paste()` รูปในคลิปบอร์ด (PNG, WebP หรือ JPEG ไม่เกิน 32 MiB) ผ่าน [`clipboard_paste.c`](../../src/clipboard_paste.c) ลงไฟล์ส่วนตัวใต้ `$XDG_RUNTIME_DIR/avernella` แล้วเปิดหน้าตัวอย่าง Send photo ไฟล์ที่คัดลอกมาจะเปิดเป็นไฟล์แนบ การวางรูปต้องใช้คลิปบอร์ดของ SDL3 ผ่าน sdl2-compat ถ้าเป็น SDL2 แบบดั้งเดิมจะวางได้แค่ข้อความ
- **คัดลอกรูป:** ใส่ PNG ลงคลิปบอร์ด (`image_clipboard()` ก็ต้องใช้ SDL3 เช่นกัน)
- **ตัวดูรูป:** `picture()` ขอรูปเต็มด้วย `photo` แล้วแสดง ทิศทางจาก EXIF ของ JPEG ถูกนำมาใช้ (`exif_orientation()`)
- **ภาพย่อ:** `ui_media_thumb()` พร้อมแคชที่มีขอบเขต (`reserve_thumbnail()`, `evict_thumbnail()`)
- **วิดีโอ:** `open_video()` ขอไฟล์ด้วย `openVideo` แล้วเล่นด้วย `ffplay` ผ่าน [`video_play.c`](../../src/video_play.c) การ์ดวิดีโอแสดงภาพตัวอย่างจาก `videoPoster` ถ้า LINE มีให้
- **คลิปวิดีโอจากกล้อง:** **Record video** ใช้ [`video_record.c`](../../src/video_record.c) ซึ่งรัน `ffmpeg` กับ V4L2 และ PulseAudio เพื่อเขียน MP4 แบบ H.264/AAC ลงไฟล์ส่วนตัว คุณดูทวนแล้วค่อยส่ง
- **ภาพหน้าจอ:** Ctrl+Alt+S หรือ **Take screenshot** ในเครื่องมือแชต [`screenshot.c`](../../src/screenshot.c) ขอผ่าน portal Screenshot ของ XDG และผลลัพธ์เปิดเป็นไฟล์แนบ
- **การบันทึก:** Save เขียนข้อมูลที่ดาวน์โหลดผ่าน `saveFile` โดยใช้ `line_save_media()` ใน worker ซึ่ง rename แบบ atomic

### การโทร

หน้าจอการโทร dock และปุ่มควบคุมอยู่ใน [`ui_media.c`](../../src/ui_media.c)

### การแจ้งว่าอ่านแล้ว

UI เป็นผู้ตัดสินว่าคุณ *เห็น* ข้อความล่าสุดแล้วเมื่อไร และ worker เป็นผู้บอก LINE `ui_conversation_presented()` ใน `ui.c` ทำงานหลังเฟรมที่แสดงบทสนทนา ถ้า `ui_read_visible()` เป็นจริง (เชื่อมต่ออยู่ หน้าต่างได้โฟกัสและมองเห็น แสดงหน้าล่าสุด เลื่อนลงสุด ไม่มีอะไรบัง) จะส่ง `markRead` สำหรับข้อความล่าสุด

`UiReadCursor` ใน `ui_private.h` เก็บรหัสสี่ค่าต่อแชต: `viewed` (ข้อความล่าสุดที่แสดงในเครื่องนี้) `confirmed` (LINE ยืนยันแล้ว) `attempted` และ `pending` ค่าเหล่านี้รับประกันว่าการยืนยันที่มาช้าจะไม่ลบป้ายของข้อความที่ใหม่กว่า และไม่ส่งการแจ้งอ่านเดิมซ้ำ `tests/ui_read.c` ทดสอบกฎเหล่านี้

## การทำงานร่วมกับเดสก์ท็อป

### Tray

[`ui_tray.c`](../../src/ui_tray.c) ลงทะเบียน StatusNotifierItem (`org.kde.StatusNotifierItem-<pid>-1`) กับ StatusNotifierWatcher ของเซสชัน ส่งไอคอนเป็น pixmap ARGB แบบ network order และเมนู `com.canonical.dbusmenu` ที่มี Open, Hide และ Quit รันบริการ D-Bus บนเธรด `line-tray` เมื่อมีโฮสต์ tray การปิดหน้าต่างจะซ่อนมันไว้ (`ui_tray_hide()`) แทนการออกจากโปรแกรม `LINE_DISABLE_TRAY=1` ปิดพฤติกรรมนี้

### การแจ้งเตือน

[`ui_notifications.c`](../../src/ui_notifications.c) เรียก `org.freedesktop.Notifications.Notify` บนเธรดอายุสั้น การแจ้งเตือนแสดงชื่อแชตโดยไม่มีตัวอย่างข้อความ ขึ้นเฉพาะตอนหน้าต่างอยู่เบื้องหลัง และเคารพการปิดเสียงรายแชตกับสวิตช์ Notifications

### เสียง

[`chiptune.c`](../../src/chiptune.c) คือชิปเสียง NES จำลอง (pulse สองช่อง triangle หนึ่งช่อง และ noise หนึ่งช่อง พอร์ตมาจากอีมูเลเตอร์ Mesen) เสียงแต่ละตัวใน `enum chip_sound` (เสียงเรียกเข้า เสียงรอสาย ต่อสายได้ วางสาย เปิดปิดกล้อง เริ่มและหยุดแชร์ ปิดไมค์ เปิดไมค์ ข้อความ) เขียนเป็นโน้ตบนรีจิสเตอร์ของชิป แล้ว render ครั้งเดียวเป็น PCM 48 kHz ใช้เวลาไม่ถึง 10 ms [`ui_sounds.c`](../../src/ui_sounds.c) เล่นผ่านเสียงของ SDL ได้ทีละหนึ่งเสียงวน (เสียงเรียกเข้าหรือเสียงรอสาย) กับหนึ่งเอฟเฟกต์ อุปกรณ์เสียงเปิดเฉพาะตอนกำลังเล่น ในชื่อสตรีม "Avernella sounds" ปิดได้ที่ **User Settings → Notifications → Sounds**

## การเพิ่มหน้าจอหรือ overlay ใหม่

1. สร้าง `src/ui_<thing>.c` และ `.h` ที่มีฟังก์ชันตามตารางรูปแบบด้านบน เก็บสถานะใน struct แบบ `static`
2. วาดด้วยฟังก์ชันช่วยใน `ui_private.h` และชุดสีใน `ui_theme.h` ห่อข้อความที่แสดงด้วย `_()`
3. ใน `event()` ของ `ui.c` ให้โมดูลของคุณได้อินพุตเมื่อเปิดอยู่ ในตำแหน่งที่ถูกต้องของลำดับ overlay
4. เรียกฟังก์ชันวาดของคุณจาก `draw_frame()` ใน `ui_draw.c` ตามลำดับ overlay เช่นกัน ระหว่างที่ overlay ของคุณเปิดอยู่ การใช้ภาพเลื่อนซ้ำต้องปิดไว้ ตรวจใน `reusable_history()`
5. ส่งคำขอไปยัง worker ด้วย `ui_rpc(method, params, tag)` และเพิ่ม `_reply()` ของคุณเข้าสายใน `handle_reply()` ของ `ui.c`
6. เรียก `_reset()` ของคุณตอนออกจากระบบ
7. เพิ่ม object เข้า `SOURCES` ใน Makefile และเข้าบรรทัดลิงก์ของ `render-bench` กับเทสต์ UI ที่ลิงก์ `ui.o`
8. ตรวจทั้งสองธีม ความกว้างแบบกะทัดรัด (≤ 640 px) HiDPI และโหมดลดการเคลื่อนไหว
